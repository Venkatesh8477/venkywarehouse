# Deployment Guide

Target architecture: Vercel hosts the Vite frontend; Render hosts the Express API; Supabase hosts PostgreSQL.

## Before Public Deployment

The Supabase database currently contains the demo admin account `admin1`, whose original demo password is known. Rotate it before exposing the API publicly. From the `backend` directory, set `ADMIN_USERNAME=admin1` and `NEW_ADMIN_PASSWORD` in your shell to a unique password of at least 12 characters, then run:

```powershell
node src/db/changeAdminPassword.js
```

The script stores only a bcrypt hash. Do not paste the password into chat or commit it. The demo seed is disabled in production and now requires an explicit `DEMO_ADMIN_PASSWORD` locally.

## Supabase Setup

1. In Supabase, open **Project Settings → Database → Connect** and copy the recommended PostgreSQL connection URI for your Render service.
2. URL-encode reserved characters in the database password.
3. Download the database root certificate from **Database Settings → SSL Configuration**. Production verifies this certificate.

## Render API

1. Connect the repository to Render and create a Blueprint from `render.yaml`.
2. Set `DATABASE_URL` to the Supabase URI and `FRONTEND_URL` to the Vercel production origin.
3. Add the Supabase certificate in Render as a Secret File named `supabase-ca.crt`. The Blueprint sets `PGSSLROOTCERT=/etc/secrets/supabase-ca.crt`.
4. Keep the generated `JWT_SECRET` and `ALLOW_PUBLIC_SIGNUP=false`. Public signup is disabled by default; users created through signup have read-only inventory access.
5. Confirm Render's health check at `/api/health` succeeds.

## Vercel Frontend

1. Import the same repository into Vercel and set **Root Directory** to `frontend`.
2. Set `VITE_API_URL` to `https://<render-service-name>.onrender.com/api`.
3. Set build command to `npm run build` and output directory to `dist`.
4. Deploy, copy the production origin, and set that exact origin in Render's `FRONTEND_URL`. Redeploy the API if the environment value changes.

`frontend/vercel.json` enables SPA route fallback. `VITE_API_URL` is embedded at frontend build time, so redeploy the frontend after changing it.

## Required Production Environment

- `NODE_ENV=production`
- `DATABASE_URL`: Supabase PostgreSQL connection URI
- `PGSSLROOTCERT=/etc/secrets/supabase-ca.crt`
- `JWT_SECRET`: at least 32 characters; generated by Render
- `FRONTEND_URL`: exact Vercel origin, such as `https://your-app.vercel.app`
- `ALLOW_PUBLIC_SIGNUP=false`

Do not put database credentials, the JWT secret, or Supabase service-role keys in Vercel frontend variables. Do not run the demo seed against production.
